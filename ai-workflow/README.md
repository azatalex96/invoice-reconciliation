# AI workflow used during this exercise

## Tools and models

**Development time**
- Claude Code 2.1.319 (I inferred the version from the bundled-skills path, because the CLI does not report it to the agent). It ran as a delegated subagent of a parent Claude Code session on Windows 11; the subagent type is not-exportable. Model: `claude-opus-5-5` (Claude Opus 5.5). The parent session wrote the task instruction, which covered rules, folder layout, readability requirements and the offline constraint. Settings: defaults, and I did not change any model parameters.
- Generated components: all code, fixtures, simulated responses, tests and docs in this folder were generated by the agent. I did not type any code by hand.
- Claude Code tools used: file read/write/edit, Bash (Git Bash), and a built-in "advisor" review call. I made two advisor calls: one before writing code and one before handing back. Their main points are below.
- Bundled skill `claude-api` (built into Claude Code, not a custom skill). I loaded it once to check the current model ID and the request shape for an image + text Messages API call. The skill recommends the server-side refusal `fallbacks` parameter, and I did **not** enable it. A refusal or truncated response is recorded as a `failed` extraction instead.
- Local runtimes: Python 3.12.4 (Anaconda), Pillow 12.0.0 (only to render the added invoice images), anthropic SDK 0.112.0 (installed, but used only through a fake client in tests). Node 24 was used only for `node --check` on the page's JavaScript.

**Inside the application**
- `recon/providers.py` → `GeminiProvider`: Google Gemini REST `generateContent` through `urllib` (no SDK). Model `gemini-3.5-flash-lite` (env `MODEL_NAME` overrides), `responseMimeType: application/json` for extraction, all other generation settings default. Requests are spaced at least 30 s apart; HTTP 429/503 are retried at most 3 times. The key is read from env `MODEL_API_KEY` and sent only in the `x-goog-api-key` header. The provider is selected with `MODEL_PROVIDER=gemini` or `--provider gemini`. **This was called for real** in a follow-up step: 16 requests in total (8 + 2 extractions, 6 notes). The coordinating session supplied the key, which went only into the command's environment and was never written to a file. A grep of this folder for the key prefix found no hits.
- `recon/providers.py` → `ClaudeProvider`: Anthropic Messages API, model `claude-opus-5-5` (env `MODEL_NAME` overrides), `max_tokens=16000`, default thinking/effort, no temperature. The key comes from env `MODEL_API_KEY`.
- The Claude path **was never called for real**, because no Anthropic key was available. Default runs use `SavedResponseProvider` with **simulated** responses (`data/model_responses/simulated/`, each labelled `"source": "simulated"`).

## One workflow example

**Instruction (excerpt from the parent task; the full text is in `ai-workflow/prompts/01-build-task.md`):** "Preserve the supplied domain rules and cases exactly; do not invent business policies… any LLM/vision step must have a deterministic offline path… include a check that the app reproduces `expected-seed-results.json`."

**What affected it:** the `claude-api` skill (model ID and request shape), and the advisor review before coding. The advisor stressed four points: (a) don't present hand-written JSON as model output, (b) keep the first occurrence of a duplicate, (c) the seed test should compare only the keys present in the expected file, (d) `MODEL_API_KEY` must be passed explicitly because the SDK reads `ANTHROPIC_API_KEY`.

**How I checked it:**
1. I wrote `data/expected-reference-results.json` by hand, with the arithmetic, *before* running the app.
2. I ran `python -m recon process` and compared the table with that file: it matched, including recoverable 2800 → 2000 cents after the correction.
3. I ran `python -m unittest` (26 tests at that point, all passing; 36 after the Gemini follow-up).
4. I ran the server and posted a correction over HTTP, stopped the server, then ran `python -m recon report` to confirm the correction persisted.

**Corrections and improvements made after checking:**
- The first draft note template repeated the billed and expected amounts twice. I trimmed it to cite the PO and receipt and give the difference once.
- The live provider first passed `output_config={"effort": "low"}`. I removed it, because that path cannot be tested here without a key and an older SDK could reject the argument. Defaults are safer for an untested path.
- My first sed edit to `data/additions.json` put unescaped quotes inside a JSON string. The JSON check caught it and I fixed it before re-running the tests.
- The second advisor review found three problems. `max_tokens=2000` could truncate live output, because thinking is always on for this model, so I raised it to 16000 and label truncation as `failed`. The batch insight said "most frequent" when no finding recurred, so I fixed the wording. And the UI JavaScript had never been executed, so I ran it under Node with a stubbed DOM for all 8 invoices, including one with a correction (the throwaway script is not part of the submission).
- **Gemini follow-up.** The coordinator's instruction (excerpt): "add a Gemini provider and save one real model run… standard library `urllib` only… Wait at least 30 seconds between live requests. On HTTP 429, back off… NEVER write [the key] to any file." I debugged everything against a fake `urlopen` first and made no live calls until the tests passed. In the single live run, 2 of the 8 extractions failed with HTTP **503** (model overloaded). That was not a status I retried. The batch continued and showed them as `failed`, which is the intended behaviour, but I then added 503 to the retried statuses, with a test, and re-requested only those two images (2 requests) instead of rerunning the batch. I checked the outcome by comparing every real extracted field with the ground-truth records (no mismatches) and by replaying the saved responses against the hand-written expectations (`tests/test_real_responses.py`).
- I decided to use simulated responses after the advisor review. They are labelled as simulated everywhere, so they can't be mistaken for real calls.

## Reproduce or replay

- Requirements: Python 3.12. Nothing else for the app or tests.
- `python -m unittest -v`, then `python -m recon process` / `python -m recon serve`.
- Replay without credentials: `python -m recon process --responses <folder>`. The default folder holds the simulated responses. The saved real Gemini run replays with `python -m recon process --responses data/model_responses/live-gemini --state data/real-run/replay-state.json`. Live runs (`MODEL_PROVIDER=gemini|claude` plus `MODEL_API_KEY`) save to `data/model_responses/live-<provider>/`.
- No hooks exist, so there is nothing to enable.

## Decisions and limitations

- A default Claude Code setup was enough for a small, single-language task, so I created no custom skills, agents or hooks.
- There is one small real run (Gemini, 8 images). Every legible field was read correctly, and the blurred image came back as all-null JSON, which validation rejected. Eight fictional invoices are not a measure of real accuracy. The Claude path is still untested against the real API.
